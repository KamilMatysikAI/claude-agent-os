# How to write persona.md

Built from interview steps 2–6. The workspace ships a template with headings and guidance comments: keep its headings, fill them, and remove the guidance comments. Use the structure below only if the template is missing.

```markdown
# PERSONA — <name>

## 1. Identity
| Field | Value |
|---|---|
| Name | ... |
| Company / project | ... |
| Role | ... |
| Language | ... |

## 2. Background
<the path so far, as a short narrative, not bullet points>

## 3. Communication style
- **Formality:** X/5 — <what that means in practice>
- **Decision style:** X/5 — <gut vs data>
- **Preferred format:** ...
- **Feedback:** ...

## 4. Values and rules
### Always
- ...
### Never
- ...
### Attitude to AI
<partner / tool / mentor / assistant, in one or two sentences>

## 5. Daily work
### Typical day
### Tools
### Current work

## 6. Blockers and tensions
<frustrations, weak spots, contradictions; no sugar-coating>

## 7. Notes for the AI
### How to talk to me
### What not to do

## 8. Energy
### What fuels me
### What drains me
### Personality tests

*Generated: YYYY-MM-DD*
```

## Rules

1. **Quote the owner** where a phrase carries meaning: "just the substance, no fluff".
2. **Invent nothing.** No extrapolation beyond what was said.
3. **Leave empty sections empty.** Better blank than made up.
4. **Be specific.** "Thinks in numbers, wants the figure before the story" beats "analytical".
5. **Map answers to sections:** step 2 → 1–2; step 3 → 3; step 4 → 4–5; step 5 → 4 (attitude) and 7; step 6 → 6 and 8.
6. **Language:** the language of the interview.
7. **Length:** follow the template's guidance (about 80 lines; never more than ~150). The file loads into every session, so every line costs attention.
8. **Facts about the business go to context.md**, not here. Keep persona about the person.
